# ExViewer iOS

供本人使用、通过 Xcode 个人签名安装的原生 iOS / iPadOS 客户端。界面采用 SwiftUI，图片由 ImageIO 解码。最低部署版本为 iOS 17；当前构建工具为本机 Xcode 27.1。

## 使用范围

使用自己的 E-Hentai / ExHentai 账号，站点实际权限、内容可见性、看图额度与归档费用均由站点决定。App 中的赞助入口对应官方 Donation 页面，提升额度并不代表无限量使用。[站点额度说明](https://ehwiki.org/wiki/My_Home)、[赞助权益](https://ehwiki.org/wiki/Donation)。

一张动图是一页。阅读时按实际文件帧数播放，翻到另一张图片才改变页码；下载和缓存保留整个文件。画廊本身提供图片内容；官方列出 GIF / JPG / WebP / PNG，并说明 APNG 可能被重采样。首版围绕画廊动图实现，没有接入额外视频站点。[支持格式](https://ehwiki.org/wiki/Making_Galleries)、[官方 FAQ](https://ehwiki.org/wiki/FAQ)。

## 当前下载

当前公开版本为 **0.1.0（39）**。在“组合搜索 → 筛选条件 → 排序”中可选择站点顺序、评分从高到低、页数从多到少／从少到多或标题顺序。评分、页数与标题只排序已加载结果；整行可点，修改先进入草稿，点击“搜索”后生效。排序随常用组合与最近搜索保存，旧记录默认沿用站点顺序。切换顺序复用已加载内容、翻页游标和在途请求，保留第 38 版的按需收藏读取及此前资料库、阅读器与双栏布局修复。公开 IPA 需要使用自己的 Apple 账号重新签名安装。

第 27 版修正最低评分筛选：在站点参数之外，按 API 的实际平均评分严格核对阈值，选择至少 3 星时排除 2.8、2.9 等低于 3 的结果，翻到后续批次仍沿用同一门槛。无法确认评分时提示重试并保留已确认的匹配项；不再将列表星星图片换算成平均分。旧评分筛选缓存会重取，其他浏览缓存继续使用。[站点评分说明](https://ehwiki.org/wiki/Gallery_Rating)。

详情页的站点原页、归档下载改为两行紧凑入口，统一图标、说明与箭头，继续在 App 内展示官方页面。页数范围沿用第 26 版的“最少页数／最多页数”两个原生表单行，留空显示“不限”，数值靠右输入，分隔线占满内容宽度。

第 25 版将组合搜索分为主页面、筛选条件、记录与常用三页。主页面保留关键词、简短筛选摘要和两个入口；站点、作者、标签、分类、评分与页数进入筛选页，最近搜索和常用组合进入记录页。记录每条只展示一份条件摘要；点选后返回主页面，来源和“已修改”状态压成一行。点选只载入编辑，点击“搜索”才更新结果；取消草稿保持此前已执行搜索，修改草稿不会自动覆盖常用组合。

从输入框进入筛选页时，内联标签、标题和上传者条件转为同一份可编辑草稿；删除标签后不会在执行搜索时重新出现。二级页面往返保留关键词、标签、作者及其他限制。

最近搜索仍按账号保存在本机，只记录已执行的有效条件，按站点和完整条件去重，保留最近 100 条。记录可删除、清空或存为常用，当前草稿也可不执行就直接保存。关键词、正负标签、作者、分类、评分、页数及其他限制一起保存。清空记录不删除常用组合。

历史记录使用各账号目录中的独立文件，原有资料库文件和下载格式保持不变。第 22 版的浏览左右滑动与第 21 版的标签大小写查找沿用。

[IPA 下载与安装说明](https://github.com/xueyj96/exviewer-ios/releases/tag/v0.1.0-build39)。公开 IPA 需使用自己的 Apple 账号重签安装，适用于 iOS / iPadOS 17.0 及以上。

## 功能与入口

本地第 29 版将底栏整理为“发现／书架／我的”。发现页的时钟打开独立“阅读历史”，保留阅读进度、排序和详情入口；书架集中管理站点收藏、手动下载和本机书签；最近搜索与常用组合统一放在搜索编辑器中。阅读历史继续使用原有阅读记录，没有新增仅打开详情就记入的浏览记录，也没有移动或改写原有账号文件。

标签候选与常用标签再次点按可取消，已选标签可整体重新编辑并一次提交；取消保留此前草稿，新标签继承当前包含／任一／排除方式。阅读历史支持最近阅读、最早阅读、标题；本机书签与手动下载支持原有顺序、标题、最近阅读，各区按账号分别记忆选择。没有阅读记录的作品在“最近阅读”排序下置后，并保留相对原序。排序仅改变展示，不修改原资料、时间或阅读进度。

作者搜索统一处理详情标签、筛选作者和文本输入三种入口。详情作者开启独立作者查询；在编辑器中修改作者替换此前的正向作者条件并保留其他筛选。相同条件忽略大小写去重，真实超过站点上限时说明哪类条件超限及实际数量。筛选图标直接打开筛选页；常用组合快捷入口先载入草稿，取消、清空、搜索和保存分别产生明确反馈。修改后执行搜索不会自动覆盖常用组合，只有明确保存时才更新或另存。

第 30 版修复本机书签和阅读历史保存后封面缺失的问题：持久化记录仍不保存临时媒体地址，显示时为可见作品补取封面源并复用现有图片缓存。请求最多每批 25 项、串行处理，合并重复作品，继续遵守站点页面和图片并发设置；切换账号或会话会丢弃旧请求结果。取不到封面时显示原因和重试入口，不改写书签、历史或阅读进度。

第 31 版将作品详情的站点收藏放到主操作区，使用原生面板读取真实分组和已有备注，支持添加、改分组、改备注和确认移除；本机书签与下载入口收进“更多”。保存只提交一次，随后重新读取该作品的站点收藏状态；响应丢失时通过只读核实判断是否已生效，无法确认时保留草稿并暂停新的提交。详情状态和书架收藏列表在提交后更新，普通收藏操作不再打开网页。

第 32 版修正详情收藏按钮的双行布局：阅读和收藏按钮保持单行，收藏分组移到按钮下方的独立说明。长分组名只截断说明文字；大字体空间不足时使用图标，同时保留完整的辅助功能标签和 44 点点击区域。

第 33 版补齐单页模式的点按翻页：左右阅读点左右区域，上下阅读点上下区域，反向阅读时前后页区域同步反转；中间区域打开设置。图片、加载占位页和缺失页面信息的占位页使用同一规则，重试按钮独立处理，双击缩放和拖动继续保留。阅读器改用透明悬浮的关闭键与单行标题，画面延伸到控件后方，不再使用整条系统导航背景；其他页面的导航样式不变。

第 34 版移除阅读画面两侧的箭头，继续支持按方向点击和滑动翻页。中间改为双击打开内置作品详情，可返回原来的阅读页；中间单击不再打开设置，阅读设置保留在底栏。长按隐藏顶栏、底栏、状态栏与系统覆盖元素，再长按恢复；单页和连续阅读均支持，加载占位页也使用同一套手势。两侧双击仍用于缩放，手势互斥以免长按、双击同时触发单击翻页。

第 35 版把阅读画布固定为完整的手机窗口，图片按屏幕中心适配；顶栏和底栏作为覆盖层显示，不再占用图片的布局高度。切换沉浸模式只改变控件可见性，保留图片边界、缩放和滚动位置；连续阅读的内容边距与图片内部滚动视图也停止自动按安全区调整。

第 36 版让收藏多选操作条替换主导航，退出或完成后恢复导航，避免两套底栏叠在一起挡住移除与分组；窄屏和大字体自动使用紧凑按钮，点按区域仍至少 44 pt。离线阅读同样隐藏底层主导航。双栏信息流保留已有卡片的列和列内顺序，封面比例回填或追加下一批时不再重新分配旧卡片；封面仍按实际比例调整高度，切换来源、排序或整批结果时重建布局。

第 37 版将本机书签改为“稍后再读”，仍使用原账号目录和 v1 的 `bookmarks` 存储字段，不复制旧记录、不新增时间戳；重启及反复读取保持原数据，阅读完成不自动移除。资料库分为“稍后再读／站点收藏／阅读历史／下载”，发现页作品长按可加入或移出稍后再读，稍后再读支持长按多选。搜索不增加本机稍后再读筛选。

阅读底栏的星标操作真实站点收藏，详情提供明确的“取消收藏”确认入口。阅读页与详情共享按账号、会话和作品区分的内存状态：详情先异步读取，点击时复用同一在途读取或 15 秒内已核实的表单，最近的提交结果及时更新各入口。提交开始先失效旧状态，保存仍只提交一次并重新 GET 核实；版本标记阻止迟到读取覆盖新结果。内存最多保存 64 项，切账号不沿用旧状态；没有后台写入队列，也不把本机稍后再读当作站点收藏。加载卡片只居中转圈和提示文字，其他表单行保持原对齐。

第 38 版进一步改为按需读取收藏表单：进入详情／阅读、翻页、缓存到期及收到本地变更通知均不触发收藏表单请求。页面只绑定本地状态，详情页直接复用本来就返回的收藏字段；只有主动打开收藏编辑器、手动刷新，或提交后核实时才读取收藏表单。15 秒仅限制已有表单是否可直接用于编辑，不会触发后台刷新。取消或读取失败不把旧表单重新标成新结果；提交结果不明仍保留草稿，不自动重发。

第 31 版尚未公开发布。普通搜索尚未确认可用的服务端排序参数；站点收藏虽有按收藏时间／发布时间排序的文档说明，但实际参数和游标契约未确认，因此未加入未经验证的远程排序。

搜索支持站点语法的常用子集：5 个包含条件、10 个排除条件、200 字符，搜索间隔至少 3 秒。普通关键词匹配标题及标签，打开标题限定后仅匹配标题；作者使用 artist 标签，上传账号另用 uploader。结构化标签按完整名称匹配，常见命名空间别名会规范化；当前不支持的作用域明确报错。元数据未取得时，屏蔽判定保持未知并暂时隐藏。[搜索规则](https://ehwiki.org/wiki/Gallery_Searching)、[元数据 API](https://ehwiki.org/wiki/API)。

build 9 标签联想使用 E-Hentai 的 `tagsuggest` 响应：英文前缀查询站点，中文只匹配随 App 提供的本机名称索引，不发送给第三方服务。词库、缓存和本机常用项会标明来源，选中后向站点核验；未核验的自由输入需明确选择“使用未验证输入”。不支持的 namespace 即使命中缓存也不能提交。联想有 300 ms 防抖、请求间隔、可取消任务和有界缓存，迟到响应不能覆盖新输入。[站点协议维护记录](https://github.com/EhTagTranslation/Editor/blob/2d4218f7074b011cb7b9da92ae97d4aba7ec7654/src/shared/ehentai/suggest-tag.ts)。

名称索引来自 [EhTagTranslation Database v7.29356.1](https://github.com/EhTagTranslation/Database/releases/tag/v7.29356.1)，源版本发布于 2026-10-26 16:44:48 UTC。当前索引含 12 个 namespace、44,766 个名称映射条目；它不是全站标签目录，也不代表每个条目都有完整中文翻译。App 内可展开“词库来源与覆盖”查看版本和覆盖说明。派生索引仅保留名称；资源目录随包保留原作者归属与 CC BY-NC-SA 3.0 CN 许可，详细摘要见 `QA/tag-source-provenance9.json`。

批量收藏直接向当前站点的 `favorites.php` 提交同源表单，使用 `ddact`、重复的 `modifygids[]` 和 `apply=Apply`，不再依赖前置页面包含完整 HTML 表单。每批最多 25 项，串行处理，移动／移除前显示数量并确认。操作失败停止后续批次，不自动重发；请求发出后若连接中断或响应无法识别，明确显示本批可能已生效、结果待核实，结束忙碌状态并保留待核实选择，由用户“刷新核实”。不把 HTTP 200 当成逐项已核验。字段协议参考维护者原始 [modifyFavorites 实现](https://github.com/EhViewer-NekoInverter/EhViewer/blob/9e1021640472ee45f35c0bb1950723db08549b9e/app/src/main/java/com/hippo/ehviewer/client/EhEngine.kt#L409-L436)，批次限制依据[官方收藏说明](https://ehwiki.org/wiki/Favorites)。

单部作品使用独立的收藏表单协议，参考维护者的 [addFavorites 实现](https://github.com/EhViewer-NekoInverter/EhViewer/blob/9e1021640472ee45f35c0bb1950723db08549b9e/app/src/main/java/com/hippo/ehviewer/client/EhEngine.kt#L362-L390)。表单只允许提交到该作品原站点和原画廊，POST 保留同源 Origin / Referer，拒绝跨域重定向；页面隐藏字段只在内存中保留。新备注按[官方文档](https://ehwiki.org/wiki/Favorites#Notes)限制为 200 个 UTF-8 字节；已存在的更长备注在未修改时原样保留，移动分组或移除不会强制截断它。保存成功以独立状态读取为准，未将 HTTP 200 当作成功。

额度解析区分账号计额、IP 动态计额和 IP 图片分辨率限制。IP 页面没有固定已用量／上限时保留未知并显示真实模式。结构依据维护者的 [HomeParser](https://github.com/EhViewer-NekoInverter/EhViewer/blob/9e1021640472ee45f35c0bb1950723db08549b9e/app/src/main/java/com/hippo/ehviewer/client/parser/HomeParser.kt#L26-L40)；赞助页按账号当前页面提取可确认的状态与说明，付款的最终官方操作保留为次级入口。

## 登录和本机数据

在 App 打开的官方网页里输入账号；Safari 已登录的状态不会自动搬进 App。网页登录的准备与捕获有操作身份和串行锁，关闭或退出后旧回调失效。会话仅存于本机 Keychain，设为 `WhenUnlockedThisDeviceOnly`；WebKit 使用非持久化数据存储。没有自建认证中转服务。

资料库按账号目录隔离，包含常用标签、屏蔽标签、稍后再读、历史、离线索引和搜索组合。会话失效或临时断网不会删除本地文件。账号切换会清空原账号额度状态，并取消原账号在途任务。

浏览缓存上限 2 GB，浏览单图最多 64 MB，浏览媒体同时传输最多 16 项、等待最多 64 项。手动下载使用独立的流式文件路径，每次一张，不经过浏览缓存；没有 10 GB 总量、64 MB 单文件或固定预留 1 GB 的人为限制。实际空间不足、文件写入失败、站点额度不足或访问失败时暂停队列，保留已完成页，等待用户恢复。手动任务与浏览分开调度，合计最多 17 项媒体传输。

当前媒体连接仅接纳已识别站点和 H@H / ehgt 的 HTTPS 地址；其他交付地址显示失败，不能视为已兼容所有 H@H 节点。

在「我的 → 阅读与存储管理 → 加载设置」用滑条调整后续图片预加载数量，点按右侧数量可精确输入，范围 0–128 张、默认 32 张；图片加载并发可选 2／4／8／16、默认 16，包含当前页和后台预载。阅读顶部与阅读设置不再放预载菜单。旧版已开启的 1–6 张设置会迁移到 32 张，关闭状态保留。0 表示关闭自动后续预加载；手指拖向相邻页时仍可按实际阅读需求加载该页。最近已完成的前 16 页和相邻页可复用，不会为保留历史而发起下载。后台至多使用所选图片并发数减一的任务槽，当前页优先；同一 URL 的在途任务在预取、预览、当前页之间切换时继续接管，原传输票据不变。快速跳页、换画廊或换账号会取消不再需要的请求；减少并发时先保留窗口内已开始的任务，完成后按新上限补充。媒体下载复用私有连接，单项取消不影响其他传输。预取文件遵守浏览缓存与传输限制，缓存被回收后按需重读，不清理手动下载。真实阅读速度以独立的手机计时样本和用户反馈为准。

build 18 将站点页面并发与图片并发分开限制：设置可选 1／2／4 路，默认 2 路时后台预载最多使用 1 路，为当前页、搜索等前台操作保留名额；选择 4 路时后台最多 3 路，选择 1 路则串行。搜索请求仍保持至少 3.1 秒的实际发出间隔；等待限额 64 项，取消等待不占传输名额。搜索或普通只读页面遇到连接中断 `-1005`，延迟后用新的私有连接最多重试一次；图片页的恢复由现有图片管线统一处理，避免两层重试相乘。收藏等 POST 写操作不自动重试。后台遇到连接中断／超时／无法连接时取消其余预载并暂停补队，暂停之后新发起的当前页成功才自动恢复；额度、验证、登录或 HTTP 429 错误仍要求明确重试。自动下一批页面信息也遵守暂停状态，翻页不等待预载完成。

从 build 16 开始，单页翻页不等待图片、解码或页面信息就绪。已知总页数范围内可以先进入目标页，加载中显示空白页、页码及当前阶段；站点给出有效文件大小时显示实际字节进度，否则显示已接收字节和不定进度。加载失败留在该页并提供重试，完成后不自动改动阅读页码。元数据按当前目标读取，有界分页，遇到无进展停止。主导航与阅读工具栏采用约 48 pt 的紧凑布局，按钮保留至少 44 pt 点按区域；窄屏阅读工具栏的书签入口移入设置。

build 17 移除发现、资料库和账号根页面的重复标题栏，EH / EX 常驻切换入口移入「账号 → 浏览偏好」并持久保存；详情和设置子页保留返回导航。发现／搜索的搜索框、条件和范围切换，以及资料库的范围、收藏分组和多选状态，组成悬浮在信息流上的半透明顶栏；页首预留操作空间，滚动时内容从其后方经过。主底栏和阅读工具栏也悬浮在内容上方，列表尾项仍可完整滚出遮挡区域。

build 18 按新的视觉要求去掉上述浮层、收藏批量操作栏、选择标记及封面重试控件的 Material 磨砂效果，改为 16% 不透明度的系统背景纯色，后方内容直接透出。搜索框和未选搜索组合的底色也减淡；悬浮位置和位置恢复逻辑沿用 build 17。阅读关闭按钮使用 30 pt 的纯色透明底、14 pt 图标和 44 pt 点按区域，并隐藏系统额外的玻璃底。

build 19 在单页图片拖动和松手动画期间只记录最后页码，动画结束后合并保存一次历史；关闭阅读、退到后台和取消动画进入设置时也保存仍有效的进度，跨账号或失效画廊上下文不能覆盖新记录。仍由 LibraryStore 串行原子保存，未改历史、书签或缓存格式。本机模拟器的中性样例比较包括 12 条历史／12 个书签和 500 条历史／250 个书签，25 次同方法操作：大样例约 1.2 MB 的同步存储单次中位约 21 ms，拖动阶段的暂存不再写文件，最终写盘移到静止时。该结果只说明主线程工作的位置和次数改变，不代表已经证明 iPhone 帧率、快速连续重抓动画或真实网络速度改善。缓存邻页沿用已解码画布；未加载图片仍可立即翻到带进度的占位页。

build 20 修正工具栏“取消”竖排：工具栏动作固定单行并使用文字自然宽度，保持 44 pt 点按高度和现有半透明纯色底。范围包括组合搜索、添加标签、保存组合等使用共享工具栏样式的页面；正文按钮继续允许换行。加载、并发、缓存、阅读历史及账号数据格式沿用 build 19。

阅读图片的文件检查、尺寸读取和 ImageIO 解码移到最多两个后台工作线程；主线程只呈现已准备好的图片。解码结果按实际像素字节计入 64 MiB LRU，最多保留 128 帧，收到内存警告后清理；同一图片的同时请求共用解码，单个消费者取消不影响其他消费者。动图提前准备后续两帧，显示时钟不再同步解码下一帧；帧未准备好时暂留当前帧。提前读取图片宽高用于稳定连续阅读布局，解码失败提供局部重试。

浏览文件缓存按账号建立一次内存索引，后续写入使用实际文件大小更新 LRU，避免每张下载完成都全目录扫描和排序。当前页及相邻已载入文件在阅读期间固定保留，离开后释放；删除成功或确认文件不存在才扣减容量。索引保持现有每账号 2 GB 浏览缓存语义，手动下载不参与回收。`QA/perf17-pipeline-results.txt` 和 `QA/perf17io/browse_cache_index_bench_results.txt` 记录本机合成样例的解码复用与索引开销；这些结果不能代替 iPhone 的真实翻页速度、帧率或网络吞吐验收。

历史 build 11 曾采用等目标渲染后落页的交接策略，该行为已由 build 16 的立即翻页和加载占位页替代。新手势、缩放、跳页或方向切换仍取消旧等待意图；相邻页元数据无进展时停止并提供明确状态与手动重试。手机安装与验收以 `QA/delivery-status.json` 的独立记录为准。

build 5 修复了 H@H HTTPS 自定义端口被误拒绝的问题：已识别的 `*.hath.network` 可使用 443 或 1024–65534；账号域和 ehgt 仍限制默认端口或 443。媒体错误保留 HTTP 状态与有界的连接错误码，封面提供局部重试。可恢复的图片源失败最多重新读取一次图片页；认证、403、网页验证、509 和 429 均不自动重试，不强制 `nl=1`。这些边界依据[官方 H@H 端口要求](https://ehwiki.org/wiki/Hentai@Home)与[官方图片故障说明](https://ehwiki.org/wiki/Technical_Issues)；Cloudflare 验证响应按[官方 cf-mitigated 标记](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/)单独识别。

清缓存保留离线文件和资料库。移除离线副本先暂存目录，再原子提交索引；提交失败回移，重开时依据持久化索引恢复中断操作。没有自动付费、自动重置额度或代替用户执行赞助交易。

## 打开与安装

1. 在 Xcode 打开 `ExViewer.xcodeproj`，选择 ExViewer scheme。
2. 在 Signing & Capabilities 选择自己的 Personal Team，选择已配对并解锁的 iPhone。
3. 运行。首次使用时按设备实际提示完成 Developer Mode / 开发者信任。
4. 在「我的」完成官方网页登录和会话验证，再测试真实搜索、收藏及阅读。

在本机 Device Hub 选择「ExViewer QA」模拟器也可以手动登录。正常启动连接真实站点；自动化测试用的 `--qa` 参数只展示中性本机样例。模拟器与手机的 App 会话分别保存，模拟器登录不会自动让手机登录。输入账号和处理验证应由本人在官方页面完成。

Simulator 构建必须保留正常签名，不能传 `CODE_SIGNING_ALLOWED=NO`。本机实际观察到未签名构建的 Keychain 操作返回 `-34018`；新构建通过正常 Xcode 签名生成模拟器应用身份。Keychain 错误会单独显示操作和数字状态码，不再被误报为空间不足。[Apple 的 Keychain 身份说明](https://developer.apple.com/documentation/security/sharing-access-to-keychain-items-among-a-collection-of-apps)。

也可使用 `scripts/install-phone.sh <设备> <自己的 Team ID>` 构建、检查签名、安装并读回目标 App 版本。脚本不处理密码、验证码或开发者协议。免费签名有效期以实际描述文件为准。
